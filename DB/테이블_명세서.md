## 데이터베이스 ERD 관계 요약

### 주요 외래키 관계

1. **사용자 중심 관계**
   - `pets.user_id` → `users.id` (사용자의 반려동물)
   - `reservation.user_id` → `users.id` (사용자의 예약)
   - `reviews.user_id` → `users.id` (사용자가 작성한 리뷰)
   - `disease_exam.user_id` → `users.id` (사용자의 AI 진단)

2. **반려동물 중심 관계**
   - `diaries.pet_id` → `pets.id` (반려동물의 다이어리)
   - `disease_exam.pet_id` → `pets.id` (반려동물의 건강 진단)
   - `reservation.pets_id` → `pets.id` (예약한 반려동물)

3. **파트너 중심 관계**
   - `partners.user_id` → `users.id` (파트너 계정)
   - `reservation.partner_id` → `partners.id` (파트너의 예약)
   - `reviews.partner_id` → `partners.id` (파트너에 대한 리뷰)
   - `consultations.partner_id` → `partners.id` (파트너의 상담)

4. **예약 중심 관계**
   - `chat_rooms.reservation_id` → `reservation.id` (예약 관련 채팅)
   - `consultations.reservation_id` → `reservation.id` (예약 관련 상담)

## 참고사항

### 정리 필요 사항

1. **pets 테이블 중복 컬럼**
   - `abti_type_code`와 `abit_type_code` 중 하나로 통일 필요
   - 현재 `abit_type_code`를 사용하는 것을 권장 (Java 코드와 일치)

2. **chat_rooms/consultations의 외래키**
   - `partner_id`가 `partners.id`를 참조하도록 외래키 제약조건 추가 필요
   - 데이터 정합성 확보를 위해 마이그레이션 필요

3. **타입 불일치**
   - 일부 테이블에서 ID 컬럼의 타입이 `bigint`와 `bigint unsigned`로 혼재
   - 통일성을 위해 `bigint unsigned` 사용 권장
